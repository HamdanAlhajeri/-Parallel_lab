ing skills in creating pre-loaded and pre-built software images. Remember that an AMI is
a template that contains the software configuration (operating system, application server,
and applications) required to launch your instance.

Task 1 – Create an AMI [10 points]
Create your own AMI with preloaded software and use it to launch an instance by fol-
lowing the steps:
   1. Repeat the steps in Lab Exercise #2 and launch an EC2 instance (Windows,
      t3.micro). Set the instance name to ‘Instance-A-<your first name>’. Once the
      instance is running, connect to it. 📷
          • Note: Keep the Administrator password securely stored. You will need it in
              later steps.
   2. Install the following software on Instance-A (you need to install at least two apps
      in total): 📷
          1. Voidtools https://www.voidtools.com/downloads (choose Installer 64-bit).
          2. WizTree https://diskanalyzer.com/download.
          3. Any appropriate lightweight app you like.
   3. Shutdown/stop Instance-A. Then create an AMI from it: Go to Instances dashboard,
      select the instance, click on Actions button, then Image and templates, and choose
      Create Image. Set the image name to ‘Image-A-<your first name>’. Wait for the
      AMI status to change to Available. 📷
   4. Terminate Instance-A. Then launch a new EC2 instance (t3.micro) but instead of
      the default Windows AMI, choose your own Image-A. Set the instance name to
      ‘Instance-B-<your first name>’. Once the instance is running, connect to it. 📷
          • Note: After launching Instance-B, keep note of its availability zone.
   5. Verify that Instance-B contains the software you installed. 📷


Task 2 – Attach an EBS and upload files [5 points]
Attach an additional EBS to your instance by following the steps:
   1. Create an empty 1 GB gp3 EBS volume. Keep the default IOPS and throughput.
      Any more than 1 GB will incur charges. Set the storage name to ‘Storage-A-<your
      first name>’. 📷
          • Note: Make sure the availability zone of Storage-A and Instance-B match.
   2. Shutdown/stop Instance-B. Then attach Storage-A to the instance.
   3. Start Instance-B and verify that Storage-A is attached by checking ‘This PC’. 📷
          • Note: If Storage-A does not show up, open the Disk Management app,
              right-click on Disk 1, choose Online, then right-click on Disk 1 again,
              choose Initialize Disk (continue with defaults), then right-click on Unallo-
              cated, and choose New Simple Volume (continue with defaults).
     4. From your own machine, open the terminal (for Windows use PowerShell, for
        macOS and Linux use Terminal). Move to the Downloads folder using cd command.
        Then execute the command.
           • Hint: In most modern operating systems, you can right-click on the
              Downloads folder and choose to open using the terminal.
           • On Windows, run Get-Date -Format o | Out-File -FilePath "your first
              name.txt".
           • On macOS and Linux, run date -u '+%Y-%m-%dT%H:%M:%SZ' > "your first
              name.txt".
     5. Copy the resulting file from your own machine to Storage-A. 📷
           • Note: Try to drag-and-drop or to copy-and-paste the file onto Storage-A.
              Some RDP clients disable this feature. You can try to enable it, or to use a
              file sharing service such as https://wormhole.app.


Task 3 – Create an AMI with EBS [5 points]
Create another AMI with a ready-to-attach EBS by following the steps:
     1. Shutdown/stop Instance-B. Then create an AMI from it. Set the image name to
        ‘Image-B-<your first name>’. Wait for the AMI status to change to Available. 📷
     2. Terminate Instance-B. Then launch a new EC2 instance (t3.micro) based on Im-
        age-B. Set the instance name to ‘Instance-C-<your first name>’. Once the in-
        stance is running, connect to it. 📷
     3. Verify that Instance-C contains the software you installed and the file you saved
        on Storage-A. 📷


Task 4 – Terminate all instances and delete all resources
Important: Access to AWS is provided to you for free. By the end of each exercise, you
need to terminate all the instances and delete all the resources you launch. Otherwise,
you will consume your free hours of credits and Amazon will charge for the running and
storage times as well as used network bandwidth.
     •    Go to Instances page, select all instances, and terminate.
     •    Go to AMIs page, select all images, and deregister.
     •    Go to Volumes page, select all volumes, and delete.
     •    Go to Snapshots page, select all snapshots, and delete.
